EvalPong – Robot autonome EvalBot (ASM ARM)

Conception et développement d’un système autonome inspiré du jeu Pong, implémenté sur robot EvalBot. Le robot agit comme une “balle intelligente” évoluant dans une arène, avec gestion des collisions, des scores et des comportements pseudo-aléatoires. L’ensemble du projet est réalisé en assembleur ARM afin de contrôler directement les registres matériels, GPIO et PWM.

🎯 Objectifs du projet

  • Créer un comportement autonome inspiré du jeu Pong.
  • Gérer les déplacements et collisions du robot en temps réel.
  • Implémenter un système de score pour deux joueurs.
  • Exploiter les GPIO, PWM et SysTick en programmation bas niveau.
  • Ajouter un comportement pseudo-aléatoire lors des rebonds.

🧠 Principe du système

Le robot démarre dans une direction aléatoire, se déplace dans l’arène et rebondit sur les obstacles. Lorsqu’il entre dans une zone “but”, un point est attribué à l’adversaire. Le jeu s’arrête lorsqu’un joueur atteint 5 points.

🧩 Architecture du projet

  • Module moteur : contrôle PWM, direction et collisions
  • Module capteurs : lecture des bumpers (GPIOE)
  • Module score : gestion des boutons et affichage LED
  • Module temps réel : SysTick + temporisations

⚙️ Matériel utilisé

  • Robot EvalBot (LM3S9B92 Cortex-M3)
  • 3 piles d’alimentation
  • Moteurs DC + pont en H DRV8801
  • Bumpers mécaniques (GPIOE)
  • LEDs intégrées (GPIOF)
  • Boutons utilisateurs (GPIOD)

💻 Implémentation logicielle

  • Programmation 100% assembleur ARM
  • Configuration directe des registres GPIO / PWM
  • Utilisation du SysTick comme base de temps et source pseudo-aléatoire
  • Gestion événementielle des collisions (interrupt-like polling)
  • Anti-rebond logiciel sur entrées mécaniques

🎮 Fonctionnement

Le programme initialise les ports GPIO et les modules PWM, puis lance les moteurs. Le robot avance en continu et réagit aux collisions :

• Bumper gauche → rotation droite
• Bumper droit → rotation gauche
• Double contact → demi-tour (180°)

Les boutons utilisateurs permettent d’incrémenter les scores, affichés via les LEDs PF4 et PF5.

Résultats expérimentaux

  • Déplacement fluide et stable via PWM matériel
  • Réaction aux collisions < 100 ms
  • Comportement pseudo-aléatoire validé
  • Score fonctionnel jusqu’à 5 points
  • Arrêt automatique des moteurs en fin de partie

📄 Analyse technique

Le projet repose sur une architecture bas niveau exploitant directement les registres du microcontrôleur. Le PWM assure le contrôle précis des moteurs, tandis que le SysTick fournit une base de temps stable et une source d’aléa. Les GPIO sont utilisés en mode événementiel pour détecter les collisions et les inputs utilisateurs.
